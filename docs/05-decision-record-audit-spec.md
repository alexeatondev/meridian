# 05 — Decision Record & Audit Trail Specification

**Version 0.3 · 2026-11-11**

Purpose: give compliance, audit and leadership complete visibility into **every signal created and every decision made** — what was decided, by which agent or person, from which inputs, under which policy, and who approved it.

## 1. Core concepts
| Concept | Definition |
|---|---|
| **Run** | One execution of a pipeline (e.g., SAA 2026-Q4) bound to one data snapshot and one policy version |
| **Step** | One agent or deterministic task within a run |
| **Signal** | Any intermediate quantitative or qualitative output consumed downstream (regime call, CMA, covariance, momentum score, manager score) |
| **Decision** | An output that selects among alternatives (CMA judge choice, vote, CIO ensemble, approval, exception) |
| **Decision Record (DR)** | Immutable ledger entry for a step, signal or decision |
| **Lineage graph** | Directed graph DR → DR showing which outputs fed which |
| **Evidence pack** | Exportable bundle (PDF summary + JSON + hashes) for any DR set |

## 2. Decision Record schema (v0.1)
```json
{
  "dr_id": "dr_01J...",                    
  "dr_type": "signal | decision | approval | exception | policy_change | agent_change | override",
  "run_id": "run_saa_2026Q4_001",
  "pipeline": "saa",
  "step": "ac-us-large-cap.cma-judge",
  "actor": {"kind": "agent | human | system", "id": "ac-us-large-cap", "version": "1.4.2",
             "model": "claude-<pinned-version>", "prompt_hash": "sha256:...", "skills": {"cma-judge": "1.2.0"},
             "code_commit": "git:abc123"},
  "portfolio_scope": ["TF-001", "SLV-USEQ"],
  "inputs": [{"ref": "dr_...", "role": "macro_view"}, {"ref": "snapshot:2026-10-31T21:00Z", "role": "market_data"}],
  "policy_version": "ips-TF001@v7",
  "output": {"schema": "cma.v1", "payload_ref": "s3://.../cma.json", "payload_hash": "sha256:..."},
  "summary": "Final expected return 6.8% (auto-blend 7.9%); valuation methods weighted 60% given CAPE≈25.",
  "rationale_ref": "s3://.../analysis.md",
  "alternatives_considered": [{"option": "auto-blend", "value": 7.9}, {"option": "historical-erp", "value": 12.5}],
  "confidence": 0.62,
  "constraints_checked": [{"rule_id": "CMA-BOUND", "result": "PASS"}],
  "dissent": [],
  "approvals": [],
  "external_sources": [{"url": "...", "retrieved_at": "...", "trust": "untrusted-web"}],
  "created_at": "2026-11-01T14:03:22Z",
  "prev_hash": "sha256:...",
  "record_hash": "sha256:..."

```
Approval DRs add: approver identity, entitlement used, reason text (required), options shown, time-on-screen, and the DR IDs reviewed.

## 3. Integrity
- Append-only table; no UPDATE/DELETE privileges for any service role.
- Each DR includes `prev_hash` (per-run chain) and is anchored daily into a run-level Merkle root stored on WORM storage.
- Payloads (JSON, markdown, data extracts) stored by content hash; evidence packs written with object lock in compliance mode for the retention period.
- Clock source: NTP-synced UTC; timestamps on every record.

## 4. What gets recorded (minimum)
| Event | DR type |
|---|---|
| Data snapshot taken | signal (system) |
| Macro regime classification | signal |
| Each CMA method estimate; judge selection | signal; decision |
| Covariance estimate | signal |
| Each PC proposal; CRO report | signal |
| Each peer review; each vote | decision |
| Revisions after review | signal |
| CIO ensemble choice and weights | decision |
| Board memo | signal (communication) |
| Compliance evaluation (each rule) | decision (system) |
| Human approval / rejection / modification | approval |
| Overrides of agent output by humans | override (reason required) |
| Exceptions | exception |
| Policy, agent, skill, model changes | policy_change / agent_change |
| Kill-switch activation | decision (human) |
| Out-of-scope action blocked | exception (system) |

## 5. Visibility features
- **"Why?" on every number:** click any weight, CMA or score → lineage view → source DRs, rationale, alternatives, dissent.
- **Signal library:** every signal type with definition, owner, method, history and hit-rate (fed by meta-learner feedback).
- **Diff views:** this run vs. last run (weights, CMAs, regime, votes) with explanations of the largest changes.
- **Replay:** re-render the exact screens an approver saw at decision time.
- **Ask Meridian (ledger Q&A):** natural-language questions answered only from DRs the user is entitled to see, with citations to DR IDs (e.g., "Why did we cut US Growth in Q4?").

## 6. Evidence pack contents
1. Cover summary (scope, period, generated by, hash).
2. Decision timeline.
3. Policy version(s) in force with text.
4. All DRs in scope (JSON) + rationales (markdown→PDF).
5. Compliance results and exceptions.
6. Approvals with reasons.
7. Agent/model/code versions and validation status at the time.
8. Integrity verification instructions and Merkle proofs.

## 7. Retention & access
- Retention period set by Compliance per entity type (doc 04 REC-3).
- Access: Audit and Compliance read-all; others scoped by portfolio entitlement.
- Legal hold flag suspends any lifecycle actions.

## 8. As implemented (pilot, 2026-11-10)
| Spec item | Implementation |
|---|---|
| Ledgers | One hash chain per run (agent and system steps, approvals, adjustments) plus a **governance ledger** (`run_id` "governance") for exceptions (`dr_type` "exception") trading (`dr_type` "trading": cashflow and position loads, setting and route changes, target tables, trade lists, rebalances, approvals, tranches, exports, fills, bulk Strategic changes, glide-path requests and decisions) and regulations (`dr_type` "regulation": tags, removals, obligation actions) |
| Access log | Separate append-only table of every user access change (who, what, before, after, reason) |
| Integrity | SHA-256 chain (`prev_hash`, `record_hash`) verified on every Console page load; database triggers refuse UPDATE, DELETE and TRUNCATE on ledger records and the access log |
| Not yet | Daily anchoring (Merkle root) and WORM copy (deferred to production: cost); payload storage is inline JSON rather than content-addressed files |
| "Why?" | Built for proposals, compliance results, capital market assumptions and risk: lists every record behind the item |
| Diff views | Built: **Changes since last run** |
| Replay, Ask Meridian, signal library | Not built |
| Evidence pack | JSON per run (`/api/runs/<run>/evidence`, **Download evidence pack** button) with integrity result; PDF summary and Merkle proofs not yet |
| Search | **Search all runs**: words, type, step, vintage, actor, dates; CSV download |
| Approval records | Approver name and email, role, decision, reason, checkbox confirmation; time-on-screen not yet recorded |
